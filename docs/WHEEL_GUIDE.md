# Колесо фортуны — гайд админа

Тут описано **как менять призы и их вероятности** без захода в логику отрисовки колеса. Этот гайд — заготовка под админ-панель: пока всё в коде, но кодстайл сделан так, чтобы потом легко перенести в БД/админку.

## Где править

Единственный файл, который трогаем — **[`src/config/prizes.ts`](../src/config/prizes.ts)**.

Там две таблицы:

1. **`PRIZE_CATALOG`** — каталог всех призов (id, цвет сектора, иконка, тир, промокод).
2. **`WHEEL_BY_LEVEL`** — какие 8 призов крутятся на каждом из 4 уровней сессии и с какими весами.

Плюс файл локализации **[`src/i18n/ru.ts`](../src/i18n/ru.ts)** → блок `prizes:` — там названия (`Приз 1`, `Приз 2`, …) для экрана результата. На самом колесе подпись берётся из `displayLabel` каталога.

## Структура данных

```ts
// PRIZE_CATALOG — массив всех призов в проекте
{
  id:            'prize-1',      // уникальный ключ, по нему ссылается WHEEL_BY_LEVEL
  i18nKey:       'prize1',       // ключ в RU.prizes (для экрана результата)
  displayLabel:  'ПРИЗ 1',       // короткая подпись на сектор колеса
  tier:          'common',       // common | rare | epic | legendary (метадата, на отбор не влияет)
  promoCode:     'LOVE10',       // опциональный промокод, передаётся в webview
  color:         0xff2e2e,       // фон сектора (визуально не виден, т.к. бекграунд — картинка, но запас на будущее)
  textColor:     '#FAF7F0',      // цвет подписи
  icon:          '🍕',           // эмодзи сверху сектора
}
```

```ts
// WHEEL_BY_LEVEL — конфиг колеса для каждого из 4 уровней
1: [
  { prizeId: 'prize-1', weight: 32 },   // первый сектор колеса L1: вес 32
  { prizeId: 'prize-2', weight: 28 },   // второй сектор: вес 28
  ...
  { prizeId: 'prize-8', weight: 1 },    // последний сектор: вес 1 (редчайший)
]
```

**Веса относительные.** `32:28:14:10:7:5:3:1` эквивалентно `64:56:28:20:14:10:6:2`. Сумма нормируется автоматически.

## Текущая бизнес-логика

Заточено под пиццерию — чтобы дешёвые ходовые призы выпадали чаще на первых уровнях, а ценные приберегались на финал:

| Уровень | Кто доминирует                  | Что меняется относительно прошлого           |
|---------|---------------------------------|----------------------------------------------|
| **L1**  | дешёвые prize-1..4              | стартовый набор: 8 common/rare              |
| **L2**  | prize-3..8 + 2 новых редких     | топ-2 ходовых из L1 (prize-1/2) удалены, prize-9/10 добавлены |
| **L3**  | prize-5..10 + 2 новых epic      | топ-2 ходовых из L2 (prize-3/4) удалены, prize-11/12 добавлены |
| **L4**  | epic + 2 legendary              | дешёвые prize-5/6 удалены, prize-13/14 (legendary) добавлены |

**Правило перехода между уровнями:**
- На следующем уровне выпадает 1–2 самых популярных приза предыдущего уровня (топ-2 по весу).
- Освободившиеся 1–2 слота занимают **новые** призы из каталога, обычно с низким весом (редкие).
- Редкие призы прошлого уровня **поднимаются в весах** (становятся типичными на новом уровне).

Логика заложена руками в массивы — никаких автоматических преобразований. Когда придёт админка, эта таблица станет UI-формой «8 строк × 2 поля (prize_id, weight) на уровень».

## Примеры правок

### Заменить приз на конкретном секторе уровня

«На L2 во второй сектор хочу поставить новый бургер»:

```ts
// 1. Добавь в PRIZE_CATALOG:
{ id: 'prize-burger-l2', i18nKey: 'burger', displayLabel: 'ПРИЗ Б', tier: 'rare',
  color: 0xff8a3d, textColor: '#FAF7F0', icon: '🍔', promoCode: 'BURGER25' },

// 2. В WHEEL_BY_LEVEL[2] поменяй второй элемент:
{ prizeId: 'prize-burger-l2', weight: 22 },

// 3. В RU.prizes добавь:
burger: 'Бургер в подарок',
```

### Изменить вероятность

«Хочу, чтобы prize-4 на L1 выпадал в 2 раза реже»:
```ts
// Было:
{ prizeId: 'prize-4',  weight: 10 },
// Стало:
{ prizeId: 'prize-4',  weight: 5 },
```

### Сделать приз эксклюзивом одного уровня

«prize-13 должен быть только на L4». Просто **не упоминай** его в `WHEEL_BY_LEVEL[1/2/3]`. Логика не подтянет несвязанный приз.

## Что НЕ нужно править

- `src/scenes/WheelScene.ts` — это рендер и анимация. Если меняешь только призы и вероятности, сюда не лезь.
- `pickPrizeIndex()`, `getWheelForLevel()`, `pickJackpotIndex()` — это математика выбора, она автоматически подхватывает изменения в таблицах.

## Подсказки для будущей админки

Когда будете строить UI-форму:

1. **Каталог призов** — табличка с CRUD: id (uneditable), label, color picker, текст-цвет, иконка, промокод.
2. **Колесо уровня** — drag-n-drop из каталога в 8 слотов уровня + ползунок веса для каждого.
3. **Validation:**
   - `prizeId` в слоте должен существовать в каталоге (иначе `getWheelForLevel` бросит исключение).
   - Сумма весов на уровне > 0 (иначе `pickPrizeIndex` упадёт с предупреждением и вернёт сектор 0).
   - Длина массива слотов на уровне = `sectorCount` колеса (сейчас 8). Если меняешь — меняй вместе с разметкой `fortune-wheel.png`.

## Тестовые сценарии

| Сценарий                              | Что проверить                                                   |
|---------------------------------------|----------------------------------------------------------------|
| Удалил приз из каталога, но он есть в `WHEEL_BY_LEVEL` | при заходе в WheelScene `getWheelForLevel` бросит исключение — лог покажет уровень + слот |
| Все веса = 0                         | `console.warn` в `pickPrizeIndex`, колесо остановится на сектор 0 |
| L4 без legendary                     | `pickJackpotIndex` упадёт к ближайшему epic; если и его нет — к сектору 0 |
